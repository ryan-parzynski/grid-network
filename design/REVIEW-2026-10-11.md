## Full finding text (preserved verbatim)

> [REVIEW-2026-10-11 C1] [PROPOSED] The sequence-number-only revocation mechanism (§18–§20) is vulnerable to replay / omission: a revoked key could be reused if sequence is replayed or if concurrent updates diverge. Recommendation: pin each KeyRevocation to the identity-stream sequence + previous_hash chain (§11, §45). See [D-04](./decisions/DR-0004-revocation-pinning.md). [OPEN D-04].
>
> [REVIEW-2026-10-11 C2] [PROPOSED] The pairing output contract (§24–§29) depends on PAKE choice without defining the independent contract (both root keys, both device IDs, session secret derivation label, transcript recording). Recommendation: define contract independent of SPAKE2 vs CPace selection. See [D-06](./decisions/DR-0006-pake.md). [OPEN D-06].
>
> [REVIEW-2026-10-11 C3] [PROPOSED] The verification procedure (§47) uses "deterministically" ambiguously and proposes a four-outcome classifier (ACCEPTED / REJECTED-INVALID / REJECTED-REVOKED / REJECTED-EXPIRED). The four-outcome proposal is [PROPOSED] and not promoted to `spec/PROTOCOL.md`. Recommendation: keep v0.6.2 three-class model in spec; place four-outcome proposal only in [DR-0003](./decisions/DR-0003-verifier-outcomes.md). [OPEN D-03].
>
> [REVIEW-2026-10-11 C4] [PROPOSED] Special case effective_sequence = 0 (§20) conflicts with pinning; KeyRevocation fields proposed to become: revocation_type, revoked_key, revoked_at_sequence, pinned_previous_hash, pinned_root_sequence, revocation_signature. See [D-04](./decisions/DR-0004-revocation-pinning.md). [OPEN D-04].
>
> [REVIEW-2026-10-11 C5] [PROPOSED] Any authority-changing object (new root, new key role, termination of identity) must require explicit acceptance; v0.6.2 lacks an explicit acceptance signal for root-compromise recovery. See [D-05](./decisions/DR-0005-identity-continuity.md), [D-09](./decisions/DR-0009-root-custody.md). [OPEN D-05, OPEN D-09].
>
> [REVIEW-2026-10-11 C6] [PROPOSED] PAKE selection (SPAKE2 / CPace) blocks pairing contract (C2) and relationship-id encoding (derived from pairing transcript, depends on D-06). See [D-06](./decisions/DR-0006-pake.md). [OPEN D-06].
>
> [REVIEW-2026-10-11 H1] [OPEN D-07] [PROPOSED] Assertions and terminations live in issuer's identity stream (v0.6.2), exposing relationship state to anyone with stream access. Proposal (Option A): per-relationship stream disclosed only to counterpart. See [D-07](./decisions/DR-0007-relationship-privacy.md). [UNCHANGED] for v0.6.2 stream placement; change proposed.
>
> [REVIEW-2026-10-11 H2] [OPEN D-09] [PROPOSED] Relationship Key role delegated by root is undefined in v0.6.2 key-roles table; needed for privacy (H1). See [D-09](./decisions/DR-0009-root-custody.md). [PROPOSED].
>
> [REVIEW-2026-10-11 H3] [REVIEW-2026-10-11] [UNCHANGED] In v0.6.2 Identity Root signs every identity document; delegation (D-09 Option A) changes this. Spec `spec/PROTOCOL.md` §9 retains v0.6.2 with PENDING DECISION callout. See [D-09](./decisions/DR-0009-root-custody.md).
>
> [REVIEW-2026-10-11 H4] [PROPOSED] Revocation propagation (§39) and local API (§47) interaction creates availability-vs-authority ambiguity. See [D-10](./decisions/DR-0010-local-api-security.md). [OPEN D-10].
>
> [REVIEW-2026-10-11 H5] [PROPOSED] Freshness attestation (§40) under-defined for offline peers. See [D-08](./decisions/DR-0008-freshness.md). [OPEN D-08].
>
> [REVIEW-2026-10-11 H6] [PROPOSED] Object identity (§41–§44) and reference stability (§18) need explicit reference-form rules. See [D-18](./decisions/DR-0018-object-identity.md). [OPEN D-18].
>
> [REVIEW-2026-10-11 H7] [PROPOSED] Revocation + local API availability: a revoked key's revocation record must remain readable; absence = failure, not authority change. See [D-10](./decisions/DR-0010-local-api-security.md). [OPEN D-10].
>
> [REVIEW-2026-10-11 M1] [PROPOSED] Relationship matching / termination scope: match on relationship_id only, not peer identity. Termination requires both-party agreement or a signed termination record. See [D-07](./decisions/DR-0007-relationship-privacy.md). [UNCHANGED] v0.6.2 concept; refinement proposed.
>
> [REVIEW-2026-10-11 M2] [PROPOSED] Protocol identifier rules (peer_id, device_id): lowercase a–z, 0–9, and punctuation `. - _ :`; maximum 128 bytes; Unicode NFC permitted only in free-text. See `spec/PROTOCOL.md` §7 (PENDING DECISION D-22). [PROPOSED].
>
> [REVIEW-2026-10-11 M3] [PROPOSED] Tighten authorization-state revocation prohibition (§16): an implementation MUST NOT grant authorization based solely on a revoked-state record. See `spec/PROTOCOL.md` §16 (unchanged v0.6.2; clarification proposed, not promoted).
>
> [REVIEW-2026-10-11 M4] [PROPOSED] Rendezvous ingestion rules (§33): accept reachability records; reject unsupported endpoints; log but not fail on unknown formats. See `spec/PROTOCOL.md` §33 (unchanged); refinement proposed. [UNCHANGED].
>
> [REVIEW-2026-10-11 M5] [PROPOSED] KeyRevocation field set proposed (§20): revocation_type, revoked_key, revoked_at_sequence, pinned_previous_hash, pinned_root_sequence, revocation_signature. See [D-04](./decisions/DR-0004-revocation-pinning.md). [OPEN D-04].
>
> [REVIEW-2026-10-11 L1] [UNCHANGED] V1 scope (§56): identity + authorization + reachability + pairing + rendezvous; no multi-device sync, no application-layer relay economics, no licensing commitment (D-25). See [D-22](./decisions/DR-0022-v1-minimal-profile.md). [UNCHANGED].
>
> [REVIEW-2026-10-11 L2] [UNCHANGED] This document is a reader's copy; source files (`spec/`, `design/decisions/`) are authoritative. Not to be cited as normative. [UNCHANGED].
>
> [REVIEW-2026-10-11 L3] [PROPOSED] Licensing unresolved. Original protocol content carries no new license claim in this design-review; see `design/decisions/DR-0025-licensing.md`. [OPEN D-25].

## How to read the tags

- **[PROPOSED]** — reviewer proposal; NOT normative; must not be cited as spec until a decision is ACCEPTED.
- **[UNCHANGED]** — carried from v0.6.2 without substantive change.
- **[OPEN D-xx]** — open decision; options/pros/cons in `design/decisions/DR-00xx-*.md`; status PROPOSED; spec retains v0.6.2 text with PENDING DECISION callout.
- Cross-reference form: `[D-06](./decisions/DR-0006-pake.md)` resolves; `[REVIEW-2026-10-11 C3](#full-finding-text)` resolves to this section.
