# Grid Network — Code of Conduct

**Revision:** 2.5

**Repository path:** `CODE_OF_CONDUCT.md`

---

## Purpose

The Grid Network project is a technical specification with
contributors from different backgrounds and disciplines. This code
describes the standards of behavior expected of everyone who
participates.

It applies to the repository, to review discussions, to issue
trackers, and to any other space where the project is discussed.

---

## Standards

**Expected behavior.**

- Assume good faith. Most disagreements are about interpretation, not
  about intent.
- Focus on the technical argument, not the person making it.
- Critique ideas and specifications, not contributors.
- Acknowledge when you are wrong, and move on.
- Give credit for prior work, including work you disagree with.
- Ask clarifying questions before assuming a position.
- Be patient with contributors who are new to the project.

**Unacceptable behavior.**

- Personal attacks, insults, or dismissal of a contributor.
- Harassment of any kind.
- Sustained disruption of technical discussion.
- Publishing private information about another contributor.
- Dismissing a technical argument because of who made it.
- Bad-faith re-litigation of settled decisions.
- Coordinated action against a contributor outside the project.

---

## Scope

This code applies to anyone participating in the project, in any
project space, at any time. It also applies when a contributor is
representing the project in public.

The code does not restrict technical disagreement. Strong technical
positions, critical review, and rejection of proposals are all within
the code, provided they are expressed about the work and not the
person.

---

## Reporting

Concerns about behavior may be raised with a maintainer. If the
concern involves a maintainer, raise it with a different maintainer
or with the stewardship entity if one exists.

Reports are handled confidentially. A reporter's identity is not
disclosed without consent.

---

## Response

A maintainer who receives a report will:

1. Acknowledge the report.
2. Determine whether the report describes a violation of this code.
3. If it does, decide on an appropriate response.
4. Inform the reporter of the outcome.

Possible responses, in increasing severity:

- A private discussion with the contributor.
- A public reminder of the code.
- A temporary restriction on participation.
- A permanent removal from the project.

The specific response is at the maintainer's discretion and depends on
the severity and pattern of the behavior.

---

## Attribution

This code is written for this project. It is not adopted from a
specific template, though it is consistent with widely used codes of
conduct in open-source and standards projects.
